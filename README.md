# 空间小狗 · Android

在房间里建立本地空间地图，放置一只三维小狗。再次打开应用时，手机从相机图像找回原来的坐标系。定位完成后可以关闭相机，在纯虚拟视图中查看小狗和惯性估计的位置，也可以选择实景查看。

## 安装

测试包为 `dist/SpacePup-0.1.0-arm64.apk`，使用开发签名。手机需要 Android 8.0 或更高版本、64 位 ARM、后置摄像头、ARCore 支持以及可用的 Google Play Services for AR。惯性模式还需陀螺仪、加速度传感器和可用的旋转向量传感器。有气压计时应用会融合相对高度。支持情况可以在 [Google 的设备列表](https://developers.google.com/ar/devices)查到。

可以把 APK 复制到手机后安装，也可以用 Android SDK 的 `adb install -r SpacePup-0.1.0-arm64.apk`。首次使用需授权相机；如果手机提示安装或更新 AR 服务，请完成该步骤。

## 第一次建图

1. 点 **创建空间** 并命名。在起点将手机朝向房间，点 **设为原点**。原点位于此时的相机位置；地图的 Y 轴向上，镜头朝前的水平方向为 −Z。
2. 缓慢横移，从不同角度反复拍同一组静止物体。墙角、书架、桌腿等比白墙、镜面和会移动的屏幕更合适。要从几个入口重新定位，就把这几个入口实际能看见的区域都拍进地图。
3. 移动手机让系统识别地面或桌面。将屏幕中央的准星对准要放置的位置，点 **放置小狗**。小狗脚底落在水平面上，鼻尖朝向放置时的手机；再次点击可调整位置和朝向。
4. 界面会显示特征点数、有效视角数和距原点的最大移动距离。三项达标且已经放置小狗后，点 **保存空间**。此时地图冻结，请横移至少 20 厘米，再看向扫描过的物体。应用用新图像连续三次独立定位，与当前 AR 位姿交叉核对，通过后才写入磁盘。复核失败会恢复采样。

## 再次进入空间

从 **我的空间** 选择地图。**定位后关闭相机** 会先打开相机寻找原房间的特征。成功后稳住手机约半秒，让速度接近零；界面会明确显示 **相机已关闭**。此时 AR 会话已暂停并释放，画面来自三维渲染。转身或走动可看到小狗的不同侧面；小狗在视野之外时，屏幕会显示方向、距离和上下角度。

**实景查看小狗** 会保留相机画面。惯性模式下可以主动点 **视觉校正**。校正成功后会显示本次校正了多少米，并在手机稳定后再次关闭相机。如果离开了扫描区，18 秒内找不到匹配就会关相机并继续惯性估计，也可以主动点 **继续惯性跟踪**。应用进入后台会停止传感器采样并释放或暂停相机；回到前台时，已有定位的会话需要重新匹配地图。

## 算法与数据

- **地图**。ARCore 提供具有米制尺度的相机位姿和平面。应用从相机的亮度平面提取 ORB 描述子，匹配多个有平移基线的视图，筛除视差太小或几何误差太大的点，再进行空间去重。一张地图最多存 12,000 个三维点。地图文件包含特征坐标、二进制描述子、小狗姿态和质量统计，采用校验和及原子替换。相机图像仅在采样时使用。
- **重定位**。新的 AR 会话可以有完全不同的原点。应用把图像特征匹配到旧地图，通过 PnP-RANSAC 求解六自由度位姿，再检查重投影误差、画面内点分布、重力方向和跨帧一致性。至少连续三帧通过才接受结果。地图质量门槛是局部采样检查，房间各处的可重定位覆盖率需要逐处实测。
- **相机关闭后**。应用把 Android 传感器坐标系和屏幕相机坐标系分别与地图对齐。旋转向量更新姿态，线加速度积分更新位移，短时静止检测用于速度归零和偏差估计。缺少线加速度传感器时会用旋转后的加速度减去重力。气压计提供相对高度约束。惯性数据中断或累计运动较多时界面提示校正。提示阈值是经验值，不能当作已标定的误差上界。
- **功耗**。纯惯性模式释放整个 AR 会话，不再采集相机图像或运行视觉匹配。运动传感器按约 50 Hz 请求采样，纯虚拟画面约 15 帧/秒刷新，后台停止采样。实际节电量取决于设备、运动和亮度，需真机对照测量。
- **本地存储**。每个空间有独立文件，保存在应用私有目录。应用未声明互联网权限，也没有上传地图的逻辑。卸载应用会删除地图。CSV 仅在手动导出时写到你选择的位置。

## 检验楼梯往返

先在平地选两个不同位置做已知距离的往返，记录中途和终点。楼层测试可由同伴携带手机在正常视野下进行。在两层分别标出参考位置并记录楼层高度。初次定位后选择关相机，走到中途、楼下、楼上和最终位置时分别记下时间和估计坐标；回到终点前保持相机关闭。到终点先记录小狗的朝向与落点，再点 **视觉校正**，读取校正距离。往返终点对齐和中途位置准确应分别评价。

返回空间列表后，可点 **导出上一段定位记录**。CSV 包含单调时钟、模式、以米为单位的三轴坐标、四元数、相机开启状态、最近一次视觉校正的距离，以及设备支持时的剩余电荷计数（µAh）。记录约每秒 4 条，保留最近 14,400 条。相同路线、相同屏幕亮度分别运行实景与惯性模式，多次比较。气压会受气流影响，手机运动持续越久惯性位置越可能漂移，尤其应实测上下楼和变换持机姿态的情形。

## 构建和回归

用 Android Studio 打开本目录，或使用 JDK 17、Android SDK Platform 35 及 Build Tools 35.0.0，在项目根目录运行 `gradlew.bat :app:assembleDebug`。Gradle Wrapper 已固定版本和分发包摘要。构建需要下载 ARCore 1.48.0 和 OpenCV 4.12.0。应用包仅包含 arm64-v8a 原生库。

`verification/Replay.java` 在桌面 JVM 中直接运行应用的视觉、存储和惯性代码。测试用不同相机位姿渲染带纹理的合成房间，建立地图并从磁盘重新加载，在新会话坐标系中找回小狗；还会改变照明、遮住部分画面、检查陌生房间和空白图像，并注入损坏的地图、传感器断流和已知三维运动。Windows 可使用同目录的 `replay.ps1`，传入 JDK 17、Android 平台 jar、ARCore AAR 的 classes.jar、OpenCV AAR 的 classes.jar 以及桌面 OpenCV JNI DLL。本次 Windows 回归使用 4.10.0 原生测试库；APK 安装的是 4.12.0 ARM 原生库。

工程还包含 Android 仪器测试入口。连接 ARM64 测试手机后，在项目根目录执行以下命令。它会使用手机 APK 自带的 OpenCV 原生库运行同一组合成测试。

```powershell
.\gradlew.bat :app:installDebug :app:installDebugAndroidTest
adb shell am instrument -w cn.spacepup.app.test/cn.spacepup.app.ReplayInstrumentation
```

如果已装交付的主 APK，也可以直接安装同次构建的 `dist/verification/SpacePup-replay.apk`，再运行上述 `adb shell am instrument` 命令。

桌面回归通过 23 项检查。一次合成房间测试保存了 1,685 个特征点，从新的会话坐标系恢复相机位置的误差为 0.0278 米，角度误差为 0.445 度。真实手机上的相机权限、AR 服务、跟踪稳定性、楼梯往返误差、覆盖率和电耗需在目标设备验证。

项目使用 ARCore 提供视觉惯性跟踪，使用 OpenCV 提取特征和求解相机位姿。小狗网格在应用中生成。[ARCore 开发者条款](https://developers.google.com/ar/develop/terms) · [OpenCV 4.12.0 许可证](https://github.com/opencv/opencv/blob/4.12.0/LICENSE)
